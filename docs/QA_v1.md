## 1. Test plan

Four layers, matching ARCHITECTURE_v1 §5. Where each layer runs is
constrained by the environment: the cloud sandbox has Python but **no
Node.js** (frontend suites cannot execute there) and a 30-second command
limit (no live TTS, no browser installs). Live-key work happens on the
homelab.

| Layer | Tool | Location | Runs in | Status |
|---|---|---|---|---|
| v0 pipeline regression | pytest | `tests/` (41 tests) | CI + sandbox | Passing (2026-10-02, 41/41) |
| Backend unit + integration | pytest + FastAPI TestClient | `backend/tests/` (110 tests) | CI + sandbox | Passing (2026-10-02, 110/110) |
| Frontend unit | Vitest | `frontend/src/**/*.test.ts` (7 files, 55 cases) | Homelab only (`cd frontend && npm test && npm run check`) | Written; **never executed** (no Node.js in sandbox) |
| E2E (Playwright) | — | — | — | **Dropped** — decision recorded in ARCHITECTURE_v1 §5.1 and §5 below |

Key invariants of the automated suites:

- **No network, no API keys** (AC-903): all TTS goes through
  `MockTTSEngine` (`backend/tests/mock_engine.py`, registered as `"mock"`);
  LLM preparation is mocked in `backend/tests/unit/test_llm_service.py`.
- **No copyrighted books** (AC-901): every test uses synthetic EPUB
  fixtures generated by `tests/fixtures/make_fixture_epub.py` (§2).
- **v0 CLIs keep working** (AC-801/802): `tests/test_v0_compat.py` runs the
  CLIs (`--list-chapters`, `--slice`, ...) as subprocesses.

### 1.1 What the backend suite covers (per milestone)

- **M1** — EPUB parsing (`test_epub_parser.py`, `test_fixture_epub.py`),
  library/reader API contracts and progress persistence
  (`integration/test_library_api.py`).
- **M2** — engine interface and adapters with mocks (`test_engines.py`,
  `test_factory.py`), cached synthesis + fallback (`test_tts_service.py`,
  `integration/test_tts_api.py`).
- **M3** — LLM preparation and voice cast (`test_llm_service.py`,
  `test_shared_preparation.py`, `test_voice_cast.py`,
  `integration/test_prepare_api.py`).
- **M4** — benchmark harness (`test_benchmark.py`, `test_benchmark_app.py`).

## 2. Fixture inventory (AC-901)

All fixtures are synthetic, generated programmatically by
`tests/fixtures/make_fixture_epub.py` (never committed as binary books):

| Fixture | Content | Exercises |
|---|---|---|
| `plain_it` | Plain narration, Italian, 2 chapters | Basic parsing, narration TTS prep |
| `plain_da` | Plain narration, Danish, 2 chapters | Danish language path |
| `dialogue_it` | Dialogue-heavy Italian (70% dialogue) | Speaker tagging, voice cast |
| `dialogue_da` | Dialogue-heavy Danish, dash dialogue | Danish speaker tagging |
| `saramago_style` | Long unmarked-dialogue sentences (Italian) | The hard alignment case (AC-405) |
| `mixed_content` | Narration + dialogue + footnotes | Mixed-content parsing |
| `edge_cases` | Empty paragraphs, special characters, mixed languages | Robustness (AC-407) |

The same generator feeds the performance harness (`benchmark_app.py` uses
`make_plain_narration_epub`) and the benchmark texts in `benchmark_tts.py`
are short synthetic passages (no copyrighted text).

## 3. Validation results

### 3.1 P0 performance, no-keys criteria (AC-601, AC-602, AC-605)

Measured 2026-10-02 with `python3 benchmark_app.py` (100 fixture books,
5 repeats per path) against the real FastAPI app via in-process
TestClient, MockTTSEngine, Python 3.12.15, cloud sandbox:

| AC | Measurement | Budget | Median | Min | Max | Result |
|---|---|---|---|---|---|---|
| AC-601 | Library load (list 100 books) | < 2000 ms | 62.3 ms | 61.0 ms | 62.6 ms | **PASS** |
| AC-602 | Chapter load (text endpoint) | < 1000 ms | 2.7 ms | 2.4 ms | 4.5 ms | **PASS** |
| AC-605 | Tap-to-audio, cache hit (synthesize endpoint) | < 50 ms | 2.1 ms | 2.0 ms | 2.2 ms | **PASS** |

Caveats, stated plainly:

- In-process TestClient excludes real HTTP/network overhead; homelab
  numbers over Docker will be higher but have enormous headroom (62 ms vs
  a 2000 ms budget).
- AC-605 measures the **backend half** of tap-to-audio (cache-hit
  synthesize response). The browser half (fetch + `decodeAudioData` +
  playback start) needs a real browser and is unmeasured; a first-ever tap
  on uncached text includes synthesis and exceeds 50 ms by design — the
  criterion is read as applying to the cached path.
- AC-606/AC-607 (memory/CPU, P1) have no profiling harness and are
  unmeasured.

## 5. E2E (Playwright) decision

ARCHITECTURE_v1 §5.1 promised ~10 Playwright E2E tests. They were never
started, and the decision is to **drop them for v1**, recorded in
`docs/ARCHITECTURE_v1.md` §5.1. Rationale:

- The cloud sandbox has no Node.js and a 30 s command limit — a Playwright
  suite could never be written, run, or verified there; committing an
  unexecuted browser suite would violate the repo rule against inventing
  test results.
- The user journeys are already covered one level down: FastAPI TestClient
  integration tests walk import → library → chapter → synthesis (AC-905),
  and Vitest covers the frontend logic (audio engine, sync, pagination,
  themes, stores).
- Playwright (+ browser binaries) is a heavy dependency; AGENTS.md prefers
  dependency-light choices.

If the owner wants browser E2E later, the homelab can add it: Node.js +
`@playwright/test`, a compose profile that serves the built frontend with
the mock engine registered, and ~10 journey specs mirroring §1.2's manual
list.
