# tts-ereader — agent instructions

AI-powered TTS eReader: LLM text preparation + voice-cast synthesis producing
read-along EPUBs with synced sentence highlighting. Read `README.md` and
`PLAN_epub3_readalong.md` first — they are the sources of truth for design
decisions and current state. Do not re-litigate decided questions (voice cast,
book-level delivery, EPUB3-over-web-app).

## Current state (2026-09-19)

- `edge_reader.py` — working hybrid engine (LLM prepare + edge-tts), validated.
- `epub_mo.py` — Media Overlays injected into original XHTML; works, 94% word
  match on test slice, self-validates output.
- `epub_readaloud.py` — simpler variant (fresh EPUB from prepared text);
  recommended output path.
- **Blocker**: Apple Books (iPhone + Mac) ignores Media Overlays in reflowable
  EPUBs. It only plays them in fixed-layout EPUBs. The primary use case
  (commute listening with lock-screen playback in Apple Books) is NOT yet met.
  Thorium Reader (desktop) is the current validation player.

## Priorities (in order)

1. **Apple Books route**: investigate and prototype a fixed-layout EPUB
   variant with Media Overlays (Apple Books plays MO in fixed-layout books).
   Likely a `--fixed-layout` mode of `epub_readaloud.py` or a new script.
   Validate structure programmatically (OPF/SMIL parse, anchors, clip
   monotonicity — reuse the validation logic in `epub_mo.py`). Real-device QA
   in Apple Books is the owner's job; make it easy for him (clear instructions
   in the PR, small test EPUB attached or generated by a script).
2. **Parallel synthesis workers**: the plan calls for cutting full-book
   generation from ~2h to 30-40 min via parallel edge-tts workers. Implement
   with asyncio or a worker pool, with unit tests using a mocked synthesizer.
3. **Dockerize**: FastAPI wrapper + Dockerfile around the pipeline
   (book-level on-demand service for the homelab, per the plan's delivery
   architecture section). You cannot run Docker in the sandbox — write it,
   lint it, and provide a `docker compose` file the owner can run at home.

## Hard constraints

- **Sandbox commands time out at 30 seconds.** Never launch long synthesis
  runs. Develop and test with tiny slices (`--slice 800` or less), mocked
  synthesizers, or synthetic test EPUBs you generate programmatically
  (there is no book EPUB in the repo — `samples/*.epub` is gitignored for
  copyright reasons; build small test fixtures instead).
- Never commit `.env`, audio files, or copyrighted book EPUBs. `.gitignore`
  already covers them — keep it that way.
- The pipeline needs `MISTRAL_API_KEY` for LLM preparation. If it is not
  available in your environment, work on code, tests, and structure; skip
  live-preparation steps rather than faking them.
- Keep `README.md` and `PLAN_epub3_readalong.md` updated with what you did —
  the owner reads those first when he returns.
- Work on a branch, commit incrementally with clear messages, and open a
  draft pull request when a coherent unit is done. One PR per priority is
  better than one giant PR.

## Style

- Plain Python 3, stdlib-first (existing code uses zipfile + ElementTree —
  match it). No new heavy dependencies without justification.
- Match the existing CLI conventions (argparse, `--list-chapters`, `--slice`).
